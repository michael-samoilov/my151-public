# League builder — phase 1 architecture

Historical captures and commands are in this folder's Git history.

Output of the architect pass, 2026-08-29. The synthesized sketch below is the
contract for `src/league/`. DECISIONS.md holds the product decisions; this file
holds the code shape.

One process note. The architect playbook calls for a multi-model arena in the
sketch phase. This container has no Codex or Grok lane configured, so both
candidates below were produced in one session and screened against the red-flag
list by hand. The candidates are structurally distinct, which is the property
the arena exists to force.

## The caller's usage, written first

```tsx
// A component renders a card row without knowing the derivation rules:
const view = useCardView(cardIndex);          // one deep hook per card
view.shades.cell;                             // theme surfaces, from the type
view.rows[6].cells;                           // [{ seat, pokemonId, isLegend }]
view.rows[6].glyph;                           // { kind: 'gym', n: 7, span: 1 }

// A gesture mutates intent, never derived state:
const place = useLeagueStore((s) => s.placeBranch);
place(cardIndex, [270, 271, 272]);            // Lotad line joins the next seat

// The selection pane is the dex builder's component, fed a different store:
<BrowserStoreProvider store={leagueBrowserStore}>
  <PokemonBrowser pickMode="instant" labelForSection={slotLabel} />
</BrowserStoreProvider>
```

## Candidates

**A — store of intent, functional core.** The persisted store holds only what
the user decided: branches per seat, boundary overrides, identity fields, slot
order. Everything shown (teams per row, glyph positions, shades) is derived by
pure functions at render time, concentrated behind one `useCardView` hook.

**B — materialized rows.** Each mutation recomputes and stores the 11 rows of
cells on the card. Components dumb-render. Rejected on the red-flag screen:
every action re-implements the derivation rules (information leakage), derived
state reaches localStorage where migrations must then repair it, and the
mutation set grows a temporal shape (place, then re-derive, then re-glyph).

**C — league as a route in the main app.** Rejected by the handoff: the page
must be its own crawlable entry with static head and body copy, not a
component swap under `/`.

**Synthesis decision.** A, with B's one good idea kept: components never call
engine functions piecemeal — `useCardView` returns the whole derived card, so
capability concentrates in one deep interface instead of scattering across the
grid, the slots, and the glyph cells.

## Types (the contract)

```ts
// intent — persisted
interface PlacedLine {
  branch: number[];              // member ids, base → final
  boundaries: number[];          // per stage: first row it may appear
}
interface GymCard {
  type: TypeName | null;
  theme: string;
  lines: PlacedLine[];           // index 0 = seat 1 = rightmost column
  signatureSeat: number | null;
  tmMoveId: number | null;
  badgeName: string;
  legend: { pokemonId: number; seat: number } | null;
}
interface LeagueState {
  name: string;
  cards: GymCard[];              // exactly 14; index → slot kind
  // actions: setName, setCardType, setCardTheme, placeBranch, removeSeat,
  // moveSeat, shiftBoundary, setSignatureSeat, setTm, setBadgeName,
  // setLegend, clearLegend, moveSlot
}

// derived — never stored
interface CardCell { seat: number; pokemonId: number | null; isLegend: boolean }
interface CardRowView { cells: CardCell[]; glyph: GlyphSpec; band?: BandSpec }
interface CardView { rows: CardRowView[]; shades: CardShades; /* … */ }
```

## The browser reuse, precisely

`PokemonBrowser` keeps its exact markup and behaviour. Three changes only:

1. Every `usePokedexStore(sel)` becomes `useBrowserStore(sel)`, where the hook
   reads a zustand store instance from `BrowserStoreContext` whose default is
   the real pokedex store. The dex builder renders bit-for-bit the same tree.
2. Two optional props: `pickMode="instant"` (tap places the line and closes
   the sheet — mobile league behaviour) and `labelForSection` (league slot
   names; the dex keeps `sectionLabel`).
3. One optional store capability: `myDexFilter/toggleMyDexFilter`. The chip
   renders only when the store defines it, so the dex builder never shows it.
   Filtering rides a new `restrictToIds` option in `useFilteredPokemon`,
   symmetric with the existing `excludeIds`.

The league bridge maps the browser's domain verbs onto league intent:
`sections` → one pseudo-section holding the open card's placed ids,
`addToSection` → `placeBranch`, `removeEvoLine` → `removeSeat`.
