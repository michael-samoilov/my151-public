# Word list

Usage guidance from the [Google developer documentation style guide word
list](https://developers.google.com/style/word-list), curated for this repo.
When a term is missing here, pick the plainest literal word and give it one
meaning throughout the document.

| Term | Guidance |
|---|---|
| above, below | Don't use for document positions. Use "earlier", "later", "the preceding section", or a link. |
| allows you to | Write "lets you". |
| and/or | Rewrite as "a or b, or both". |
| app, application | Both are fine. Pick one per document and keep it. |
| as | Don't use to mean "because". |
| backend | One word, noun and adjective. |
| cell phone | Write "mobile phone" or "phone". |
| check, uncheck | For checkboxes, write "select" and "clear". |
| click | Pointer devices only, and never "click on". For touch, write "tap". |
| currently, now | Don't use. Describe the present behavior in present tense with no time marker. |
| data | Singular: "the data is". |
| desired | Write "wanted", or rephrase around what the reader does. |
| dialog | Not "dialogue" for UI. "Dialog" alone; "dialog box" only if ambiguous. |
| disable, enable | For UI, prefer "turn off" and "turn on". For states, "inactive" and "active". Fine for flags and API fields in code font. |
| double-click | Hyphenated. |
| e.g. | Write "for example". |
| easy, easily, simple, simply, just, quickly | Delete. They judge the reader's experience. |
| email | No hyphen, lowercase. |
| enter, type | "Enter" covers typing or pasting a value into a field. "Type" means literally typing. |
| etc., and so on | Avoid. Write "such as x and y", or finish the list. |
| filename | One word. |
| frontend | One word, noun and adjective. |
| grayed out | Write "unavailable" or "inactive". |
| hit | Don't use for "press", "click", or "type". |
| hover | Write "hold the pointer over". |
| i.e. | Write "that is". |
| in order to | Write "to". |
| internet, web | Lowercase. |
| kill | Prefer "stop" or "end". The `kill` command stays in code font. |
| leverage, utilize | Write "use". |
| log in, login | Prefer "sign in" (verb) and "sign-in" (modifier). Match the product's own label. |
| master, slave | Don't use. Write "main", "primary", "replica", or "worker". |
| may | Ambiguous. Write "can" for ability or "might" for possibility. |
| once | Use for a count. For sequence, write "after". |
| please | Don't use in instructions. |
| plugin, plug in | "Plugin" is the noun; "plug in" is the verb. |
| pop-up | Prefer "dialog" or "window". |
| prior to | Write "before". |
| repo | Fine after "repository" appears once. |
| roadmap, soon, will support | Don't promise futures. Document what exists. |
| sanity check | Write "validation" or "quick check". |
| screenshot | One word. "Take a screenshot". |
| setup, set up | "Setup" is the noun or adjective; "set up" is the verb. |
| should | Reads as optional. Write "must" or the bare imperative for requirements, "we recommend" for advice. |
| since | Use for time only. For cause, write "because". |
| tap | Touch devices. |
| that, which | "That" introduces a restrictive clause, no comma. "Which" introduces a nonrestrictive clause, with a comma. |
| toggle | The control is "a toggle". As the action, write "turn on" or "turn off". |
| via | Write "by using", "through", or the specific mechanism. |
| vs. | Spell out "versus". |
| website, webpage | One word, lowercase. |
| while | Use for time only. For contrast, write "although" or "whereas". |
| whitelist, blacklist | Write "allowlist" and "blocklist". |
| will | Present tense instead: "the build fails", not "the build will fail". |
| wish, desire | Write "want". |
| workaround, work around | "Workaround" is the noun; "work around" is the verb. |
