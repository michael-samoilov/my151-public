# Build pipeline

This extends "Build Verification" in `CLAUDE.md`.

`npm run build` is exactly `npm run i18n:verify && tsc -b && vite build`. npm runs `prebuild` first: it deletes the saved type-check state when the installed packages changed, because `tsc -b` does not compare package type files. The `tsc -b` step covers `src`, `api`, `scripts` and `e2e` via the project references in `tsconfig.json` — note that `api/` is Vercel serverless code that Vite never touches, so this typecheck is its only local gate. **Sprite caching is not part of the build**; it is a separate, manual `npm run cache-sprites`.

Vercel runs `npm run build:vercel`: `tsc -b --clean`, so every deploy type-checks from scratch, then the same build, then `scripts/keep-previous-assets.ts`. On production builds it copies in the `/assets` files of the deploys from the last 7 days (50 MB at most), so a tab opened before a deploy still loads the code it started with. Keep values that change on every deploy out of the JavaScript: one such value renames most chunks (`src/lib/buildVersion.ts`).

`npm run i18n:verify` (`scripts/i18n/verify.ts`) is the deterministic i18n gate. It holds every type name to the string dumped from Scarlet/Violet's own `typename` table, and checks placeholder integrity, untranslated-copy detection, Unicode hygiene, CJK case safety and length budgets. It reads only checked-in files, so it needs no network. Its type-name fixture is `docs/i18n/sources/scarlet-violet-typenames.json`, regenerated by the separate, manual `npm run i18n:game-text`. That command and the other manual i18n generators, such as `npm run i18n:names`, download their inputs. None of them is part of the build.
